# 运行说明

## 环境

系统运行在树莓派 Linux 和 ROS2 Humble 环境中。采用 Docker 部署时，可将宿主机 `/home/pi/cucumber_picker` 挂载到容器 `/home/ubuntu/cucumber_picker`。程序从项目目录的 `models/best.onnx` 加载模型。

Python 依赖见 `requirements.txt`。`rclpy`、`sensor_msgs`、`geometry_msgs` 和 `cv_bridge` 由 ROS2 环境提供，相机驱动使用 `realsense2_camera`。部署时应确认运动学扩展与设备的处理器架构和 Python 版本匹配。

串口默认 `/dev/rrc`，波特率 1000000，可通过 `RRC_DEVICE` 修改。同一控制板不要同时运行多个串口控制进程；SDK 相机测试与 ROS2 相机驱动也应分别运行。

## 调试顺序

1. 检查供电、相机、串口和运动学库。
2. 按 README 启动 640×480 彩色流与对齐深度流。
3. 运行 `python3 main_picker.py --skip-init`，检查预览、检测和坐标。此模式跳过归位和采摘，但仍连接串口。
4. 核对主程序内参、`--camera-ee-offset` 与 `--target-offset`。更换相机或安装位置后重新确认参数。
5. 运行 `python3 fixed_xyz_test.py --xyz 0.20,0.00,0.40` 检查求解结果。添加 `--move` 才会发送目标运动命令。
6. 固定点验证通过后，使用 `python3 main_picker.py --enable-pick --single-shot --approach-only` 检查接近位置。
7. 接近位置正确后移除 `--approach-only`，验证夹取、旋转、释放和复位。`--single-shot` 用于限制同一锁定目标重复执行；默认动作结束后清空锁定并开始下一轮识别。需要观察单轮动作时，可配合 `--keep-locked-after-motion` 保留锁定状态。

## 参数

| 参数 | 默认值及含义 |
| --- | --- |
| `--conf-threshold` | 0.75，置信度阈值 |
| `--detect-every-n` | 每 3 帧检测一次 |
| `--depth-roi-size` | 9，中心邻域边长 |
| `--lock-frames` | 5，目标位置累计帧数 |
| `--min-camera-depth` / `--max-camera-depth` | 0.08 / 0.80 米，软件深度筛选范围 |
| `--camera-ee-offset` | 相机到末端平移偏置，单位米 |
| `--pick-pitch` | 预设抓取俯仰角，单位度 |
| `--preview-port` | 8080；0 关闭网页预览 |

深度参数用于筛选视觉目标，机械臂能否到达由逆运动学求解判断。完整选项见主程序 `parse_args()`。

## 故障定位

无图像时检查驱动、话题、对齐配置和 ROS_DOMAIN_ID；无检测时检查模型及 ONNX Runtime。运动学加载失败时检查扩展架构、Python ABI 和 ROS2 依赖。

检测线程与图像回调异步运行，定位使用最近一次检测框。目标移动或检测间隔较大时，可适当减小 `--detect-every-n` 并观察坐标变化。出现定位偏差时，依次检查深度单位、相机内参、安装轴向、平移偏置和基座坐标，分段验证视觉定位与机械臂执行结果。
